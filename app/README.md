# 应用包

本目录是 Dify 应用「匠枢」的两种导出形式，任选一种导入。

| 文件 | 格式 | 适用 |
|---|---|---|
| `jiangshu.ifpkg` | Dify 应用包（zip，含 manifest） | **推荐**，Dify 1.18+ 直接导入 |
| `jiangshu.dsl.yml` | 纯 DSL（YAML） | 兼容旧版导入，也方便直接看配置 |

两个文件内容一致，都来自同一次导出。`dsl.yml` 就是 `ifpkg` 包内 `app.yaml` 的原样副本。

## 导入方式一：应用包（推荐）

工作室 → 创建空白应用 → **导入应用包** → 选 `jiangshu.ifpkg`

## 导入方式二：DSL

工作室 → 创建空白应用 → **导入 DSL 文件** → 选 `jiangshu.dsl.yml`

## 导入后必须手动补两样

DSL 不包含这两项，因为它们是实例相关的：

**① 模型供应商的 API Key**

集成 → 模型供应商 → SiliconFlow → 设置 → 填 Key

默认模型要设成：

| 用途 | 模型 |
|---|---|
| 系统推理 | `deepseek-ai/DeepSeek-V3` |
| Embedding | `BAAI/bge-m3` |
| Rerank | `BAAI/bge-reranker-v2-m3` |

**② 重新绑定知识库**

打开「知识检索」节点，把两个知识库重新勾选一遍。库 ID 是实例相关的，导入后会指向不存在的库。

## 应用结构

```
开始（用户输入）
  └→ 知识检索（两个库 · TopK 4 · Rerank bge-reranker-v2-m3 · 阈值关闭）
       └→ LLM（DeepSeek-V3 · temperature 0.2 · 上下文绑定检索结果）
            └→ 直接回复（{{#llm.text#}}）
```

## 提示词在讲什么

这是整个应用最值钱的部分，全文在 `jiangshu.dsl.yml` 的 `prompt_template` 里。六条规则，核心是第 4 条：

> 禁止出现检索内容中未出现的：材料牌号、公司名、百分比、秒数、温度值、公式、文档名。包括以"建议""大约""比如"开头的估算，也不允许。

另外两条容易忽略的设计：

- **不让模型写来源**（第 6 条）。引用由 Dify 系统自动标注，模型没机会编文件名。早期版本就是因为让模型自己写来源，编出过三个不存在的文档名。
- **不使用反问**。删掉了早期“缺少材料信息就先追问”的规则，因为模型会把它执行成“每句话都反问”，体验很差。

## 导出时注意

Dify 导出时会问是否包含密钥，**选不包含**。本目录的两个文件都已确认不含 API Key。
